プレースホルダで実トークンを用意できないことによる。TOC と Markdown 描画は DB シート側（B-10a / B-13b-1）で確認できたため、
経路ごとに分けて記録している。

`/view/db` の DB 取得失敗フォールバックは 9 巡目に実測済み。**再現条件に注意**があり、
`DATABASE_URL` / `SKILLSHEET_OWNER_ID` を「外す」方法では届かない。`app/layout.tsx` が全ページで
`assertServerEnv()` を先に呼び、この 2 つは必須扱いなので、外すとページ内の `try/catch` ではなく
グローバルのエラー境界を測ることになる。値は present のまま**接続先を到達不能にする**のが正しい条件。
加えて Next のデータキャッシュ（`.next/cache`）に正常時の結果が残っていると古い描画が返るため、
キャッシュを消してから起動する必要がある。

### D-2 の測り直し（18 巡目）— 汚染と測り方、2 つとも直した

16・17 巡目の D-2 は 2 つの意味で信用できなかった。どちらも Codex の指摘で、どちらも当たっていた。

**(1) 検証用シート自体に過去の巡の書き込みが残っていた。**
16 巡目の証跡は 1 社の社名が `C5 recovered <epoch>` のままだった。17 巡目でそこだけ戻したが、
**指摘された 1 フィールドしか直していなかった**のが誤りで、自己PR も `C-13 dirty <epoch>` のままだった。

そこで、フィールドを 1 つずつ潰すのをやめ、**親ブランチ（本番・dogfooding 中は一度も書き込んでいない）と
全ブロックを md5 で突き合わせて**汚染を洗い出した。残っていたのは次の 4 つ。

| ブロック | 汚染 | 由来 |
|---|---|---|
| project | 会社[0] の社名が `C5 recovered <epoch>` | C-5（自動保存） |
| profile | `pr` が `C-13 dirty <epoch>` | C-13（離脱警告） |
| project | 案件[0] の `process` から「要件定義」が 1 個欠落 | C-7（工程選択） |
| project | 案件[0] の `tech.lang` に `DogfoodTag` が混入 | C-7（技術タグ入力） |
| — | profile と stats の `order` が入れ替わり | C-3（並べ替え） |

全部戻したうえで、シート全体の指紋（`order:type:md5` を並べた文字列の md5）が
**本番と一致すること**を確認した — 両方とも `8435f6410597cdcd2d48f54664592e24`（9 ブロック）。
以降の D-2 はこの状態で測っている。

**(2) probe が短すぎて誤ヒットしうる測り方だった。**
値の先頭 6 文字を probe にしていたため、`I・K` / `8` / `年` / `4` / `名` / `28歳` のような短い値は
probe が値そのものになり、PDF 内の無関係な日付・人数・年齢に当たって「出ている」と数えられた。
stats を label / value / unit で別々に見ていたのも同じ穴で、**stats ブロックが丸ごと落ちていても
`12/12` と出せる**状態だった。以前この行に書いていた「profile 11/11 / stats 12/12」はこの測り方の数字。

直した点は 3 つ。

1. probe は値の先頭ではなく**値そのもの**を使い、正規化後 8 文字未満は
   ヒット扱いにせず `tooShortSkipped` に落とす（`年齢28歳` / `最寄り駅成田駅` / `学歴高卒` の 3 件）。
   落ちた項目は、それらを含む連結 probe（`profile:meta全項目`）で担保する
2. **面ごとに probe を分ける**。stats は PDF が `statsBlockToMarkdown()` の表（ラベル行 → 値行）、
   画面が `stat-row.tsx` のカード（value → unit → label）で並びが違う。同じ probe を両面に当てると
   必ずどちらかが外れる。1 版でこれをやって「stats が画面に 0 件」と出し、危うくアプリの欠落として
   報告しかけた
3. 正規化から `·`（U+00B7）が抜けていた。画面の meta 行 `年齢 28歳 · 勤務形態 …` の区切りで、
   これを落とさないと項目をまたぐ連結 probe が画面側だけ必ず外れる

## 棄却した主な指摘

反証で落としたもののうち、判断が分かれそうなものを残す。

- ダークテーマでカード面とページ地のコントラストが 1.04:1 → `globals.css` に「Console: 影なし（ヘアライン境界のみ）」と設計意図が明記されており、意図的なトークン設計
- 「30+案件」と実件数 32 件の不一致 → `30+` は下限表記で 32 はこれを満たす。KPI はシート作成者の自己申告値で集計値ではない

- 空のテキスト（markdown）・職務経歴ブロックを追加して保存すると、リロードで消える（4 巡目に実測。DB のブロック数も増えない）→ `blocks.ts:373` の `isBlockInputEmpty` による意図的な drop。コメントに「保存時の drop と、全消し保存ガードで共有する単一の真実」と明記があり、`builder-client.tsx:221` は空ブロックを dirty 判定からも除外して「案件エディタタブを開いただけで幽霊ブロックができる」のを防いでいる。内容を入れれば残るので、データ損失ではない。ただし**追加した空ブロックが「保存しました」の後で黙って消える**点はユーザーから見ると驚きがあり、告知が無いのが妥当かは設計判断として残る（今回は逸脱に数えていない）
