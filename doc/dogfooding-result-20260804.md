検証は 160 件の一次指摘を挙げたうえで、1 件ずつ「反証する側」で再検証し、
仕様どおりの挙動・元データ側の記述揺れ・測定条件の誤りに起因するもの 100 件を棄却した。
残った 60 件を重複統合し、2 巡目以降に見つけた分を足して **32 件**の逸脱にまとめ、
**子 Issue 24 本**（#136〜#153 / #155〜#160）として起票している。

1 巡目で未実施だったケースは 2 巡目で、レビューで「サブステップが未検証」と指摘された分は
3〜12 巡目で実際に動かした。残る `BLOCKED` は `/view/[path]` 経路の描画に依存する
**B-10b / B-13b-2 / B-15b の 3 ケース**で、これはこの環境の `GITHUB_TOKEN` がプロキシ用
プレースホルダで実トークンを用意できないことによる。TOC と Markdown 描画は DB シート側（B-10a / B-13b-1）で確認できたため、
経路ごとに分けて記録している。

`/view/db` の DB 取得失敗フォールバックは 9 巡目に実測済み。**再現条件に注意**があり、
`DATABASE_URL` / `SKILLSHEET_OWNER_ID` を「外す」方法では届かない。`app/layout.tsx` が全ページで
`assertServerEnv()` を先に呼び、この 2 つは必須扱いなので、外すとページ内の `try/catch` ではなく
グローバルのエラー境界を測ることになる。値は present のまま**接続先を到達不能にする**のが正しい条件。
加えて Next のデータキャッシュ（`.next/cache`）に正常時の結果が残っていると古い描画が返るため、
キャッシュを消してから起動する必要がある。

> したがって上記のパスは**検証を実施した環境にしか存在せず、この文書の読者が直接開くことはできない**。

### D-2 の 4 点突合（7 巡目）

過去の巡で立てた hidden フラグを全て戻した素の状態（会社 19 / 案件 32、画面 32/32 件、PDF 19 ページ）で、
元データ・正本 DB・画面・PDF を全件突合した結果。

| 対象 | 元データ | 正本 DB | 画面 | PDF |
|---|---|---|---|---|
| 会社 | 19 | 19 | 19 | 19 |
| 案件 | 32 | 32 | 32 | 32（※） |
| スキル | 46 | 34 | 34 | 34 |

- **元データ → 正本 DB でスキルが 46 → 34**。ここが唯一の欠落段で、D-1（#137）に対応する。
  名前が一致しないものは 13 件あるが、うち `Nest.js`（元データ）と `NestJS`（DB）は同一スキルの
  表記ゆれなので、**実際の欠落は 12 件**（Java / WordPress / Expo / GraphQL / Sanity CMS (GROQ) /
  Prisma / CakePHP / Vitest / Playwright / Jest / Turborepo / Biome）
- **正本 DB → 画面 → PDF は件数一致**。スキル 34 件・会社 19 件は 3 情報源すべてに揃っている
- ※ 案件は 32 件すべて PDF に出るが、1 件だけタイトルが `【PatentStart-】` と**不正なハイフン入り**で
  描画されるため、完全一致検索では 31 件に見える。データ欠落ではなく P-1（#146）のハイフン挿入が
  タイトルにも及んでいるもの。画面側は `【PatentStart】` と正しい
- 案件は元データ側も **32 件**で一致する。当初 30 件しか拾えなかったのは抽出正規表現が
  `#### ■ <数字>.` の連番形式だけを見ていたためで、会社「個人開発」配下の 2 件
  （HorseManager 第二弾 / HorseFeeders 第一弾）が連番を持たず漏れていた。`^#### ■` で数えると 32 件
- タイトルまで突合すると 1 件だけ差がある。元データ「モバイル推薦システム開発（連合学習 + クラウド基盤）」に対し
  DB は「モバイル推薦システム開発」で、括弧部分が落ちている（D-9 / #160）。落ちた語自体は同案件の
  `summary` に残っているのでタイトル欄だけの短縮だが、**件数一致のまま中身が削られる欠落**なので
  逸脱として起票した。件数だけの突合ではこの種の退行を検出できない

## 棄却した主な指摘

反証で落としたもののうち、判断が分かれそうなものを残す。

- ダークテーマでカード面とページ地のコントラストが 1.04:1 → `globals.css` に「Console: 影なし（ヘアライン境界のみ）」と設計意図が明記されており、意図的なトークン設計
- 「30+案件」と実件数 32 件の不一致 → `30+` は下限表記で 32 はこれを満たす。KPI はシート作成者の自己申告値で集計値ではない
- 一覧カードに氏名が出ない → 単一オーナー運用（`SKILLSHEET_OWNER_ID` で固定フィルタ）のため全カードが同一表記になり解決にならない
- ビュー全 OFF 時に空状態メッセージが無い → sticky なトグルが常時表示されており 1 クリックで復帰できる
- 会社名は匿名化されているのに製品名は実名 → 元データ側の記述であってアプリの逸脱ではない
- 空のテキスト（markdown）・職務経歴ブロックを追加して保存すると、リロードで消える（4 巡目に実測。DB のブロック数も増えない）→ `blocks.ts:373` の `isBlockInputEmpty` による意図的な drop。コメントに「保存時の drop と、全消し保存ガードで共有する単一の真実」と明記があり、`builder-client.tsx:221` は空ブロックを dirty 判定からも除外して「案件エディタタブを開いただけで幽霊ブロックができる」のを防いでいる。内容を入れれば残るので、データ損失ではない。ただし**追加した空ブロックが「保存しました」の後で黙って消える**点はユーザーから見ると驚きがあり、告知が無いのが妥当かは設計判断として残る（今回は逸脱に数えていない）
