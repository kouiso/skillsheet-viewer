## 決まりと裁定（今日受けたもの）

### 持ち主の裁定（マネージャー経由）

- **main（本番）へのマージ:** 「中身がOKなら問題ない」。ゲートが全部揃えばマージしてよい。マージは 1 件ずつ。マージのたびに本番の画面を確かめる。本番が壊れたら、すぐに戻しの PR を出してマージする。
- **CI:** 「CIはローカルで通れば通ったものとみなしていいよ」。
  - その head で lint・type-check・test・build・check-naming をローカルで回し、`LOCAL-CHECK | head | コマンド | pass n fail n | UTC` の形でコメントに残す。
  - ローカルで落ちたらゲートは通らない。
  - 実際の CI が通っていないのに、通ったとは書かない。
- **デザイン:** 「デザイン通りになるように全部作ること」。
  - 画面に何が出るかは、デザインボードを正とする。
  - 項目の有無・順・プラン・課金は、仕様書を正とする。
  - 板と同じ大きさ（1280×860、390×844）で並べた画像を証拠にする。
- **順番:**
  - 既存の PR → 今週・来週のイテレーション → claude-cloud ラベルの無い issue。
  - ラベルやイテレーションを書き換えて順番に合わせることはしない。
  - GitHub Project は 403 で読めないので、イテレーションによる並べ替えはしていない。
- **-ux の人の担当・起票・所有の項目には触らない:** 今日は該当が 0 件。

## 当たった壁と越え方

- **GitHub の二次レート制限（12:55Z ごろと 14:03Z ごろ）**
  - 書き込みが短い間に重なったのが原因。
  - 越え方: 書き込みは全部リードがまとめて出す。メンバーとレビュアーはファイルに書いて返す。間隔は 60 秒あける。
- **Vercel の無料枠（1 日 100 デプロイ）を 13:16Z ごろに使い切った**
  - preview と本番の Vercel の status が failure になる。
  - マージのたびに本番を確かめる決まりなので、マージは止めている。
  - 戻るのは 13:16Z の 24 時間後ごろの見込み。
- **GraphQL・Projects v2 が 403、rerun_failed_jobs も 403**
  - REST の `gh api` は使える。
- **画像の URL**
  - 40 桁の SHA を入れた画像の URL は、ツールで壊れる。7 桁の SHA を使う。
- **隔離 DB**
  - initdb は root では動かない。ubuntu か postgres のユーザーで、`unshare -n -p -f --mount-proc` の中で動かす（`script/e2e-isolated-db.sh`）。
- **共有の git 設定**
  - まだ remote に無いブランチの fetch refspec を入れると、ほかの worktree の fetch がすべて落ちる。入れない。
- **worktree の共有**
  - レビュアーと書き手が同じ worktree を使うと、互いの変更を消す。レビュアーは自分の detached worktree を使う。
- **プロセスの止め方**
  - 止めるのは、自分で立てたものを PID 指定でだけ。pkill・killall・名前やユーザーで止めることはしない。
- **マシンの負荷（load average 20〜29）**
  - 負荷で時間切れになった試験は、そのファイルだけ `--maxWorkers=1` で回し直し、両方の結果を書く。
